# 프로젝트 위험 — factory-3d-viewer

사람과 에이전트가 이 프로젝트의 설비 · 스택 · 외부 시스템을 건드리기 전에 읽는다.

## 실제 외부 시스템 — 시험에서 절대 닿지 않는다

- 사업관리시스템 로그수집 API(`https://log.smart-factory.kr/apisvc/sendLogData.json`)는 정부 사업 시스템이다. 실제 인증키로 보낸 로그는 그대로 기록되고 되돌릴 수 없다. 시험은 가짜 서버(로컬 HTTP 스텁)로만 보내고, 실제 주소 · 실제 키를 시험 환경에 넣지 않는다.
- 같은 키로 10분 안에 두 번 보내면 실제 시험 결과가 흐려진다(AP1029). 운영 중인 키로 수동 전송도 하지 않는다.
- Gmail SMTP 계정(.env 의 SMTP_*)은 실제 메일을 보낸다. 시험은 가짜 SMTP 서버로만 보낸다.
- 구글 휴일 달력은 시험에서 가짜 HTTP 서버가 주는 고정 iCal 로 바꾼다(네트워크에 기대지 않는다).

## 공용 DB — 시험에서 쓰지 않는다

- Windows PostgreSQL `175.193.55.102:5432` 는 SmartDash · FEMS · KPI · CNC 수집 등 여러 서비스가 함께 쓰는 운영 DB 다. 시험은 여기에 접속하지 않는다. 전송 이력 테이블(`tp23.sf_log_history`, `tp1.sf_log_history`)이 필요한 시험은 버리는 PostgreSQL 컨테이너에 같은 모양의 테이블을 만들어 쓴다.
- 이 DB 에 스키마 · 테이블 · 열을 만들거나 바꾸지 않는다. 운영에서도 기존 이력 테이블에 행을 더하는 것뿐이다.

## 운영 스택 — 건드리지 않는다

- 운영 컨테이너 `factory-3d-viewer`(https://twin.smartline.kr)와 앞으로 생길 sf-daily 운영 컨테이너 · 전용 DB 컨테이너를 시험 때문에 멈추거나 다시 만들지 않는다.
- `gateway` 컨테이너 · `~/projects/gateway/` 설정은 이 프로젝트 작업에서 바꾸지 않는다.
- `sl-influxdb` · `sl-db` 등 다른 프로젝트 컨테이너를 건드리지 않는다.
- `.env` 는 운영 비밀값이다. 읽어서 시험에 쓰지 않고, 고치지 않고, 커밋하지 않는다. `docs/ops/접속정보/` 도 같다.

## 시험 환경(하네스)

- 이 서버는 운영 서버다. 호스트에 패키지를 설치하지 않는다(npm · apt · pip 금지). 빌드 · 시험은 모두 Docker 컨테이너 안에서 한다.
- 시험용 컨테이너 · 네트워크 · 볼륨은 이름에 `sfdaily-test` 를 넣고, 시험이 끝나면 지운다. 호스트 메모리가 빠듯하므로 오래 남기지 않는다.
- 시험용 PostgreSQL 은 호스트 포트를 열지 않는다(컨테이너 네트워크 안에서만).

## git

- `main` 브랜치는 건드리지 않는다. 작업은 `linux-server` 에서 갈라진 브랜치에서 한다.
- `git push` 하지 않는다(원격은 다른 사람 저장소이고 Vercel 배포가 걸려 있다).
