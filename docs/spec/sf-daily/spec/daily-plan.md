# daily-plan — 하루 계획은 업체 · 그날마다 한 번만 정하고 다시 정하지 않는다

> 상태: 살아있는 계약 · 독자: 구현자 / 오케스트레이터
> 산출물: sf-daily
> 이음새: 그날 하루 계획 → `sf-daily/api/daily-plan.md` · 업체 명부 → `sf-daily/spec/companies.md`
> 단언: 같은 자리의 `tests/sf-daily/daily-plan/GATES.md`

## 목적 / 의도

업체마다 그날의 로그인 · 조회 · 로그아웃 보낼 시각을 업체 명부의 시각 범위 안에서 무작위로 정하고, 한 번 정한 계획을 그날이 끝날 때까지 그대로 유지한다. 서비스가 다시 시작돼도 같은 계획을 돌려준다.

## 언어 · 런타임

Node.js(ES 모듈). 계획은 공유 PostgreSQL 에 sf-daily 전용 자리로 남는다.

## 의존 도구 · 시스템

- PostgreSQL — 전송 이력과 같은 서버. sf-daily 전용 스키마 `sf_daily` 를 쓴다.
- 업체 명부 — `sf-daily/spec/companies.md`(업체 목록 · 시각 범위).

## 입력

- 그날(KST 날짜) 하나.
- **설정**
  - `PG_PASSWORD`(필수) — 공유 PostgreSQL 비밀번호. 비어 있으면 runner 가 시작하지 않는다.
  - `PG_HOST`(기본: 공유 DB 서버) — 비어 있으면 기본값을 쓴다.

## 출력 (계약)

1. **그날 하루 계획**: 업체 명부의 업체마다 로그인 · 조회 · 로그아웃 계획 시각(KST, 초 단위). 모양은 `sf-daily/api/daily-plan.md`.

## 핵심 로직 (동작)

### 1. 계획 시각은 업체 명부의 시각 범위 안에 있다

- **로그인 계획 시각은 그 업체 유형의 로그인 범위 안에 있다.**
- **조회 계획 시각은 그 업체의 로그인 계획 시각 + 30분 이상, + 3시간 미만이다.**
- **로그아웃 계획 시각은 그 업체 유형의 로그아웃 범위 안에 있다.**
- **계획 시각은 범위 안에서 고르게 무작위로 고른다.**

  같은 범위에서 계획을 여러 날 뽑으면 범위의 앞쪽 · 뒤쪽에 고루 퍼져야 한다. 범위 시작에 몰리면 업체마다 시각이 달라지라는 요구를 못 지킨다.

### 2. 같은 그날 두 업체의 로그인 계획 시각은 같은 분에 들지 않는다

- **그날 다섯 업체의 로그인 계획 시각을 분 단위로 자르면 모두 다르다.**

### 3. 계획은 업체 · 그날마다 한 번만 정한다

- **같은 그날을 두 번 이상 요청하면 처음 정한 계획과 같은 계획을 돌려준다.**
- **서비스가 다시 시작된 뒤 같은 그날을 요청해도 처음 정한 계획과 같은 계획을 돌려준다.**
- **두 곳에서 동시에 같은 그날 계획을 처음 요청해도 남는 계획은 하나다.**

  계획을 다시 뽑으면 이미 지난 시각이 새 시각으로 바뀌어, 한 단계를 두 번 보내거나 건너뛸 수 있다.

### 4. 계획은 기록으로 남는다

- **정한 계획은 그날이 지나도 지워지지 않는다.**

  어느 날 어느 업체를 몇 시에 보내기로 했는지 나중에 대조할 수 있어야 한다.

## 이 모듈에 없는 것

- 그날이 영업일인지 — `business-day`. 이 모듈은 요청받은 그날의 계획을 정할 뿐이다.
- 계획 시각이 지났는지 · 보낼지 — `runner` · `step-sender`.
