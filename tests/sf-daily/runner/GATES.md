# runner — 게이트

> 계약: `docs/spec/sf-daily/spec/runner.md`
> 구현: 이 폴더 · 시험 결속 규약: `tests/lib/README.md`
> 두 자리에서 잰다. 서비스 프로세스(`node sf-daily/main.js`)는 시작 거부 · 떠 있음 · 회차 간격 · 표준 출력 · 멈춘 회차 · 종료 신호를, 회차 하나씩은 `createRunner(deps)` 에 가짜 시계와 가짜 이음새(`world.js`)를 주어 잰다.
> 켜진 서비스는 `SF_DAILY_FAKE_NOW` 로 띄울 수 없으므로(6절) 켜진 서비스 프로세스의 시각은 미리 읽히는 시험 시계(`tests/lib/fake-clock.js`)로 옮긴다. 꺼진 서비스는 `SF_DAILY_FAKE_NOW` 를 쓴다.
> 회차 시험의 가짜 계획(KST): A 로그인 10:30:10 · B 10:40 · C 10:50 · D 11:00 · CDR 10:10, 조회 · 로그아웃은 `world.js` 의 PLAN. 회차는 따로 적지 않으면 30초마다다.

## 명제

### RN-01. SF_DAILY_ENABLED 가 true · false 가 아니면 시작하지 않는다

- **등급**: 핵심
- **겨누는 조항**: 1절 「설정 표의 시작 거부 조건 중 하나라도 걸리면 … 걸린 설정 이름을 모두 출력하고 0 이 아닌 코드로 끝난다」 · 설정 표 `SF_DAILY_ENABLED`
- **판정**: 값이 `yes` · `TRUE` · `1` 이면 15초 안에 0 이 아닌 코드로 끝나고 출력(표준 출력 · 오류 출력)에 `SF_DAILY_ENABLED` 가 있다. RN-01 ~ RN-09 의 서비스는 `SF_DAILY_FAKE_NOW` 없이 시험 시계로 03:00 KST(때가 된 것 없음)에 띄운다 — 거부 까닭이 잰 설정 하나뿐이게.
- **구현 상태**: 구현됨 — `tests/sf-daily/runner/process.test.js::RN-01`

### RN-12. 회차 간격은 SF_DAILY_TICK_SECONDS 초다

- **등급**: 일반
- **겨누는 조항**: 설정 표 `SF_DAILY_TICK_SECONDS` 「시각을 확인하는 간격(초)」 · 3절 「오류 응답 · … · 10분 대기 … 이면 범위 끝 전까지 다음 회차에 다시 요청한다」 · 출력 3 「보내기 결과 … 한 줄씩」
- **판정**: 로그수집 API 가 늘 AP1029 를 주는 영업일 11:58 KST(유형2-3 로그인이 때가 됨)에 간격 10 으로 띄우면, 34초 동안 실행 기록 줄의 묶음(3초 넘게 떨어진 줄끼리 나눈 것)이 셋 이상이고 묶음 시작 사이가 8초 이상 14초 이하다.
- **구현 상태**: 구현됨 — `tests/sf-daily/runner/process.test.js::RN-12`
